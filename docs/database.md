# Database

`database/migrations/001_initial.sql` creates the normalized ledger; `002_seed.sql` adds
interactive and simulator accounts, four instruments, and explicit development
inventory. `003_long_only_positions.sql` adds the nonnegative-position backstop and the
active-sell reservation index. The official PostgreSQL image applies these in lexical
order to a new Compose volume.

## Tables

- `users` owns identity/profile data; `accounts` owns trading status and separate available
  and reserved cash.
- `instruments` is the symbol reference table.
- `orders` stores client idempotency UUID, durable/engine identity, account, instrument,
  side/type, original and remaining quantity, price, and lifecycle status.
- `trades` references both durable orders and accounts and preserves the engine trade ID.
- `positions` has one row per account/instrument and stores settled owned quantity. Active
  sell orders are the reservation ledger rather than a second mutable position counter.
- `risk_events` stores category, severity, JSONB metrics, explanation, and time.
- `outbox_events` records committed business events for reliable future publication.

All primary keys use `GENERATED ALWAYS AS IDENTITY`; the application never computes
`MAX(id)+1`. Foreign keys enforce ownership, unique constraints enforce idempotency and
engine identity, checks prevent invalid quantities/prices/balances/statuses, and indexes
support account orders, recent instrument trades, risk history, and unpublished outbox
scans.

Money and price ticks are `BIGINT` cents. Position quantity has a nonnegative check because
APEX is long-only. Position average price is fixed-precision `NUMERIC(20,4)`. Timestamps
are `TIMESTAMPTZ` and generated by PostgreSQL or converted from engine epoch milliseconds.

The positions endpoint derives three authoritative values from PostgreSQL: `quantity` is
settled ownership, `reserved_quantity` is the sum of `remaining_quantity` for the same
account/instrument's `PENDING`, `NEW`, and `PARTIALLY_FILLED` sell orders, and
`available_quantity` is their difference. The partial
`orders_active_sell_reservation_idx` supports that query without maintaining a duplicate
aggregate.

For a clean development schema run `make reset && make run`. `make stop` preserves the
named `postgres_data` volume. The host port is 55432; containers use `postgres:5432`.
